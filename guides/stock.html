Stock & Inventory

Step-by-step guide to managing inventory in InnoVisions ERP: multi-warehouse stock, transfers, cycle counts, reorder alerts, batch tracking, and valuation.

Module: Stock & Inventory Difficulty: Advanced Prerequisites: At least one warehouse configured, stock items created with costing method assigned

The Stock & Inventory module provides comprehensive inventory management across multi-warehouse, multi-bin environments with full serial and batch traceability, consignment stock handling, and landed cost integration. The system supports multiple valuation methods simultaneously — FIFO layer management, weighted average recalculation, and standard cost variance posting — with real-time inventory valuation reconciliation to the general ledger. Advanced warehouse management features include zone-based pick optimization, cross-docking, wave picking, and ABC-driven cycle counting with KPI tracking.

Configure Advanced Warehouse Management

1
Set up zones and aisles for pick optimization

Define warehouse zones (bulk storage, fast-moving,冷藏, QA hold) and configure aisle-rack-shelf hierarchies within each zone. Assign pick sequence priorities per zone to optimize pick-path routing. The system uses zone-based slotting to recommend bin assignments for new stock receipts based on item velocity and dimensions.

2
Configure put-away rules by product category

Define put-away strategies per item category — hazardous materials route to designated zones, fast-moving items to forward pick locations, bulk items to reserve storage. Rules can be based on item attributes (weight, volume, storage condition) or ABC classification. The system suggests the optimal bin on receipt.

3
Set warehouse role permissions

Configure granular permissions per warehouse — assign users or roles to specific functions: receiving, put-away, picking, dispatching, cycle counting, and transfers. Role-based dashboards show only relevant warehouse operations. Audit trail captures all warehouse operations with user attribution.

4
Configure cross-docking

Enable cross-docking for items that bypass put-away and move directly from receiving to dispatch. Set up cross-docking rules based on customer orders, item categories, or supplier agreements. The system identifies cross-dock eligible receipts at goods receipt entry and generates put-away-to-dispatch instructions.

5
Set up wave picking

Configure wave picking parameters — order grouping rules (by carrier, shipping zone, delivery route), wave release schedules, and pick cart assignment. Waves consolidate multiple orders into a single pick run to minimize travel time. The system generates pick lists sorted by bin sequence and validates pick accuracy.

Implement Serial Number Tracking

1
Define serial number assignment rules

Configure when serial numbers are assigned — on receipt (pre-printed labels or system-generated), on sale (assigned at point of dispatch), or on production completion. Define the serial number format with prefix, length, and check digit rules. Serial numbers can be scanned via barcode or RFID for accuracy.

2
Implement serial number validation

Configure validation rules to prevent duplicate serial number entry across warehouses and items. Set up format validation using regex patterns. Enable serial number reservation at sales order entry to prevent double-allocation. The system validates serial numbers against the item master and existing stock.

3
Use serial number inquiry and traceability

Access the serial number inquiry screen to look up any serial number and see its full lifecycle — receipt date, supplier, warehouse bin history, sales order, customer, warranty status, and service history. The inquiry supports both forward tracing (from component to finished good) and backward tracing (from finished good to supplier batch).

4
Track warranty by serial number

Configure warranty terms per item (duration, coverage type, service level). The system calculates warranty expiry dates from the sale date or production date stamped on the serial record. Generate warranty expiry reports and integrate with the service module for warranty claim processing.

Info

Serial number traceability supports full forward and backward tracing — from finished good back to supplier batch, or from component lot to all shipped products.

Set Up Batch/Lot Tracking

1
Create batches on receipt

For batch-tracked items, the system prompts for batch entry at goods receipt. Batches can be auto-generated (sequential or date-based format) or manually entered from supplier documentation. Each batch record stores the receipt date, supplier, PO reference, and initial quantity.

2
Configure batch attribute tracking

Define custom attributes per item category — manufacturing date, expiry date, best-before date, country of origin, supplier batch reference, quality grade, and test results. Attributes are captured at batch creation and used for allocation rule evaluation (e.g., FEFO picks nearest expiry first).

3
Set up FIFO/FEFO allocation rules

Configure allocation strategies per item — FIFO (oldest receipt first), FEFO (nearest expiry first), or LIFO (newest receipt first). The system applies the allocation rule at picking and reservation time. Override options allow manual batch selection with supervisory approval for non-standard picks.

4
Implement batch hold and release for quality

When quality issues are identified, place affected batches on hold — stock is blocked from picking and dispatch. The hold can be partial (specific quantity) or full (entire batch). Quality control users inspect and release batches, or initiate a return to supplier. The batch hold log provides full audit trail.

5
Generate batch traceability reports

Run the batch traceability report to trace a batch through the supply chain — from raw material receipt through production consumption to finished good dispatch to customer. The report supports lot genealogy views showing parent-child batch relationships. Export for regulatory compliance submissions.

Manage Consignment Stock

1
Set up consignment supplier

Configure suppliers as consignment suppliers in the supplier master — this enables consignment-specific transaction types and valuation rules. Define the consignment agreement terms, including payment trigger (on consumption), minimum stock commitments, and return authorization rules.

2
Process consignment receipt without ownership transfer

Receive consignment stock using the consignment receipt transaction — stock is added to available quantity but ownership remains with the supplier. The system tracks consignment stock separately from owned stock in inventory reports. No GL posting is made for consignment receipts as no ownership transfer has occurred.

3
Record consignment consumption and invoicing

When consignment stock is consumed (sold to a customer or used in production), the system triggers a consumption event. The consumption generates a purchase invoice from the consignment supplier at the agreed price and posts the corresponding inventory and COGS entries. The supplier can be paid on a consumption summary basis.

4
Run consignment stock valuation

Generate the consignment stock valuation report showing consignment stock on hand by supplier, item, and warehouse with agreed unit costs. This report is used for balance sheet disclosure — consignment stock is not recognized as owned inventory but disclosed as a commitment. Reconcile consignment quantities with supplier statements.

Warning

Consignment stock is not owned by your company until consumed. It must be tracked separately from owned inventory for accurate balance sheet reporting.

Configure Landed Costs

1
Define landed cost types

Set up landed cost categories — freight, insurance, customs duties, handling fees, inspection costs, and port charges. For each cost type, define the GL account for cost accrual and the allocation method (by value, weight, volume, or quantity). Configure whether the cost is estimated at PO creation or entered after receipt.

2
Configure allocation basis

Select the allocation basis per landed cost type — by value (distribute proportionally to item line value), by weight (per kilogram), by volume (per cubic meter), or by quantity (per unit). For mixed containers, the system can use a weighted combination of bases. The allocation basis is applied across the items in the shipment.

3
Post landed costs to inventory value

When landed costs are entered against a goods receipt, the system posts to a landed cost clearing account and automatically allocates the costs to the inventory value of the received items. The average cost of each item is updated to include the allocated landed costs. The GL impact shows the debit to inventory and credit to the cost accrual account.

4
Handle estimated vs actual cost

Landed costs can be estimated at PO creation based on expected freight rates and customs percentages. When actual costs are known (after receipt), enter the actual amounts and the system revalues the inventory and posts the variance to a landed cost variance account. The variance analysis report compares estimated vs actual landed costs per shipment.

Info

Landed costs can be estimated at PO creation and adjusted when actual costs are known. The system revalues the average cost automatically.

Perform Cycle Counting Program

1
Configure count frequency by ABC classification

Perform ABC analysis on inventory — A-class items (top 80% of value) count monthly, B-class (next 15%) quarterly, C-class (remaining 5%) annually. Configure the system to auto-generate count schedules based on classification. Count frequency can be overridden for items with high shrinkage risk or regulatory requirements.

2
Choose blind count vs system-count methods

Select between blind count (counter sees no system quantity — prevents bias) and system-count (system quantity displayed for verification). Blind counts reduce counting bias but may require recounting for large variances. Configure the method per item category or count schedule. The system records count method for audit trail.

3
Set up count approval workflow

Configure variance thresholds that trigger approval — counts with variance under 2% auto-approve, variances 2-5% require supervisor review, over 5% require manager investigation and root cause documentation. The approval workflow captures comments and corrective actions before adjustment posting.

4
Post adjustments with GL impact

Approved count adjustments post to inventory with automatic GL journal entries — inventory increase debits the inventory account and credits a count adjustment account; decreases reverse the entry. The GL impact is calculated at the item's current average cost. Unapproved adjustments are held in a pending adjustments queue.

5
Track count accuracy KPIs

Monitor cycle count performance through the count accuracy dashboard — KPI metrics include count accuracy percentage (matches / total counted), inventory record accuracy, count variance value, and count completion rate vs schedule. Trend analysis shows accuracy improvement over time and identifies problem areas requiring process improvement.

Tip

Use ABC analysis reports to classify inventory by value. Focus cycle counting resources on A-class items (80% of value).

Run Inventory Forecasting

1
Select forecast models

Choose from forecasting models — moving average (simple or weighted), trend-adjusted (Holt's method), seasonal (Holt-Winters), or demand-driven (using sales history with promotional uplift). Configure the historical period length (12-24 months recommended) and the forecast horizon. The system evaluates model fit using MAPE (Mean Absolute Percentage Error).

2
Track forecast vs actual

Run the forecast accuracy report to compare forecasted demand against actual sales. The report shows forecast error metrics — bias, MAPE, MAD, and tracking signal. Items with consistently high forecast error are flagged for manual review. Use the accuracy feedback loop to adjust model parameters or switch models for specific item groups.

3
Calculate safety stock based on service level

Configure target service levels per item (95% for A-class, 90% for B-class, 85% for C-class). The system calculates safety stock using the formula: safety stock = Z-score × standard deviation of demand during lead time. Lead time variability is factored in for items with unreliable supply. Recalculate safety stock after each forecast update.

4
Enable demand-driven replenishment

Configure demand-driven replenishment parameters — dynamic reorder point (forecast-based), order-up-to level, and review period. The system generates replenishment suggestions calculated as: order quantity = (forecast demand during lead time + safety stock) - current stock on hand. Suggestions can be converted to purchase requisitions or transfer orders.

Set Up Automated Reorder Rules

1
Configure dynamic reorder points

Set up reorder points that adjust automatically based on lead time variability and demand trends. The dynamic reorder point formula: reorder point = (average daily demand x average lead time) + safety stock. Lead time variability is calculated from actual supplier performance data. Reorder points are recalculated daily or weekly depending on item velocity.

2
Calculate economic order quantity

Enable EOQ calculation for order quantity optimization: EOQ = sqrt((2 x annual demand x ordering cost) / holding cost per unit per year). Enter ordering costs (processing, freight minimums) and holding costs (storage, insurance, obsolescence) per item or category. The system suggests order quantities that minimize total inventory costs.

3
Choose min-max vs reorder point methods

Select the replenishment method per item — min-max (order up to max when stock falls below min) for stable demand items, or reorder point (order fixed quantity when stock hits reorder point) for variable demand. The system supports hybrid approaches where seasonality-driven items use reorder point with seasonal adjustment factors.

4
Configure supplier-specific lead times

Maintain supplier-specific lead times per item — some suppliers may have longer or more variable lead times than others. The system uses the preferred supplier's lead time for reorder point calculation. Lead time performance is tracked against actual delivery dates and feeds back into the lead time database for continuous improvement.

5
Convert auto-suggestions to purchase orders

Review the auto-suggestion report showing items below reorder point with calculated order quantities, preferred suppliers, and expected delivery dates. Select items and convert to purchase orders with a single action — the system creates POs with supplier, items, quantities, and requested delivery dates pre-populated. Unconfirmed suggestions are retained for next review cycle.

Handle Negative Stock Controls

1
Configure negative stock prevention rules

Set inventory control policies — prevent negative stock entirely (hard block), allow with warnings (soft block), or allow with manager override. Configure the prevention rules per warehouse or item category. High-value or serial-tracked items are typically hard-blocked, while low-value bulk items may allow soft-block with automatic reorder trigger.

2
Configure backflushing for manufacturing

Enable backflushing for manufacturing environments where components are automatically consumed from inventory when the finished good is produced. Configure backflushing at work order completion or at specific production steps. Backflushed quantities use the BOM component ratio. Negative stock caused by backflushing is flagged and reported separately.

3
Investigate negative stock events

Run the negative stock investigation report to identify items with negative balances, the transactions that caused them, and the date/time of occurrence. Common causes include unregistered goods receipts, incorrect backflushing, data entry errors, and missing purchase order receipts. Assign root cause categories for trend analysis.

4
Process correction journals

When negative stock is identified, create inventory correction journals to adjust quantities and values. The correction journal posts the offsetting entry to bring stock back to zero or positive. All correction journals require a root cause code and managerial approval. The system prevents correction journals from creating negative stock in other items.

Warning

Changing the costing method on an item with existing stock requires a full inventory revaluation. Test the impact in a sandbox environment first.

Configure Stock Valuation Methods

1
Manage FIFO layers

When using FIFO, each receipt creates a cost layer with quantity and unit cost. Outbound transactions consume layers in chronological order. View the FIFO layer report showing all open layers by item and warehouse with remaining quantity and cost. The system validates that the total value of all layers equals the inventory GL account balance.

2
Configure weighted average recalculation frequency

Set the weighted average recalculation trigger — on every receipt (continuous average), daily, weekly, or monthly. The system recalculates the average cost as: (current inventory value + receipt value) / (current quantity + receipt quantity). Choose period-end recalculation for month-end closing or real-time for more current valuation.

3
Post standard cost variances

When using standard costing, the system tracks purchase price variances (difference between PO price and standard cost) and usage variances (difference between actual and expected usage). Variance accounts are pre-configured in the GL mapping. Run the variance analysis report to understand cost drivers and update standards based on actual trends.

4
Handle valuation method changes

Changing an item's costing method (e.g., from weighted average to FIFO) triggers a full inventory revaluation. The system calculates the value under the new method and posts the adjustment to a revaluation reserve account. Run the revaluation impact report before committing the change. Method changes are date-effective and audited.

5
Reconcile stock valuation to GL

Generate the stock valuation reconciliation report comparing inventory value per the Stock module against the GL inventory account balance. The report breaks down reconciling items — goods received not yet invoiced, invoiced not yet received, WIP valuation, and count adjustment differences. Investigate and clear reconciling items before period close.
